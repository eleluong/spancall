\begin{abstract}
Most function-calling systems decode JSON token by token, even when every argument value is already present in the dialogue or tool schema (\textbf{Stratum F}). We present \textsc{SpanCall}, a non-autoregressive alternative that recasts groundable function calling as slot-and-span extraction over a 395M-parameter \texttt{ModernBERT-large} encoder. By jointly encoding tool and parameter anchors with the dialogue and canonical context literals, \textsc{SpanCall} combines a tool-selection head with a type-filtered, boundary-factorized span pointer network decoded via exclusivity-constrained search. Trained on a 1:1 corpus-balanced mix of Hermes V1 and xLAM-60k (117,760 training instances) and evaluated on a distribution-matched benchmark ($n{=}1{,}735$, $n_F{=}1{,}277$ per corpus), \textsc{SpanCall} achieves 0.743 and 0.766 \texttt{exact\_F} (0.755 macro average; 0.711--0.799 on unseen schemas and paraphrases). Against two hosted LLM baselines (\texttt{google/gemma-4-26b-a4b-it} and \texttt{openai/gpt-oss-120b}) on identical examples with 10,000-resample paired bootstrap CIs, \textsc{SpanCall} beats both LLMs by +32.3 to +35.3 points on Hermes and matches them on xLAM (within 1.2 points, statistically tied) at $38.8\times$--$91.3\times$ lower amortised latency, while outperforming both on scalar calls (0.798 and 0.840 vs.\ 0.360--0.397 and 0.755). Deployed as a speculative fast path with abstention-gated LLM fallback (\textbf{Router}), \textsc{SpanCall} reaches 0.807--0.808 macro \texttt{exact\_F}---statistically outperforming both LLMs on every corpus---while cutting LLM calls by 82.4\% and tokens by 80\%. Adding a deterministic post-$H_1$ schema-type gate (\textbf{Router+Schema}) that routes \texttt{array}/\texttt{object} tools directly to the LLM lifts macro \texttt{exact\_F} to \textbf{0.855--0.857} (0.821--0.825 Hermes, \textbf{0.889} xLAM; +11.1--11.2 points over both LLMs on xLAM) while still cutting LLM calls by 65.7\% and tokens by 60\%.
\end{abstract}
