\section{Introduction}

Nearly every tool-calling pipeline today treats a function call as a generation problem \citep{patil2023gorilla,schick2023toolformer,yao2023react}. To produce something like \texttt{\{"origin": "Hanoi", "date": "2026-10-24", "seat\_class": "BUSINESS", "nonstop": true\}}, a causal LLM runs 25--45 sequential decoding steps, most of them spent on JSON punctuation, and it can still emit a schema-invalid value unless wrapped in a grammar constraint \citep{willard2023outlines}.

Generation is the right tool when arguments must be composed: code, free-form text, or values that depend on several reasoning steps. We call this regime \textbf{Stratum A}. But many everyday calls look nothing like it. Filters, bookings, CRM updates, and device commands need values already present in the request, in recent dialogue, or in the schema's enum list. We call this \textbf{Stratum F}, and there the payload is an extraction problem wearing a generation costume: a bidirectional encoder can fill it in one parallel pass and cannot invent a value absent from its input.

\paragraph{Why an extractive caller is not just an NER model.}
Dropping autoregressive decoding sounds straightforward until one tries it. Classical slot-filling and extractive QA models \citep{devlin2019bert,su2022globalpointer} assume a fixed label set and a flat answer, and function calling breaks that in three ways. Tools and parameters are unknown at training time, so the model must condition on schemas it has never seen. Arguments may have several surface mentions, may need a value that is not a substring of the input, and may hold a list or nested object under strict JSON typing. And per-slot extractors trained independently tend to assign the same entity to several same-type slots---\emph{pointer collapse}---which for \texttt{origin}/\texttt{destination} turns a fluent prediction into a wrong one.

\paragraph{What we build.}
\textsc{SpanCall} is a non-autoregressive slot-and-span architecture on a 395M-parameter bidirectional encoder (\texttt{ModernBERT-large}; \citealp{warner2024modernbert}). Candidate tools and parameters, including flattened leaves for nested \texttt{object} schemas, become query anchors encoded jointly with the utterance and a pool of canonical literal spans $\Omega$. $H_1$ scores tool anchors; $H_3$ scores start and end boundaries plus span widths for every slot at once, after a type filter prunes the candidates. A multi-positive objective stops repeated mentions from counting as errors, an exclusivity-constrained DFS picks non-overlapping spans, and a two-step variant re-encodes only the selected tool when many tools are in play. The goal is deliberately narrow: absorb groundable calls quickly and hand the rest back to the LLM.

\paragraph{Contributions.}
\begin{itemize}
    \item \textbf{An anchor-conditioned multi-head pointer architecture} (\S\ref{sec:method:model}) that combines anchor-based tool selection ($H_1$), deterministic type-compatibility pre-filtering, and a boundary-factorized span pointer network ($H_3$) in one encoder pass over a 395M-parameter backbone.
    \item \textbf{Exclusivity-constrained joint decoding and two-step scaling} (\S\ref{sec:method:decode}). Pairing $H_3$ with a value-aggregated DFS decoder eliminates pointer collapse, and two-step decoding re-encodes only the selected tool so accuracy stays flat from 1--2 tools (0.777) through 6--10 tools (0.758) on xLAM.
    \item \textbf{Fair cross-corpus evaluation, balanced training, and speculative routing} (\S\ref{sec:setup}, \S\ref{sec:results}). Trained on a 1:1 balanced mix of Hermes V1 and xLAM-60k (117,760 instances) with macro-averaged dev selection, \textsc{SpanCall} reaches 0.874 macro dev exact call (0.882 peak on a disjoint probe), 0.743 \texttt{exact\_F} on Hermes eval and 0.766 on xLAM eval (0.755 macro), and 0.711--0.799 zero-shot on full unseen-schema and paraphrase splits. Evaluated head-to-head against \texttt{google/gemma-4-26b-a4b-it} and \texttt{openai/gpt-oss-120b} with 10,000-resample paired bootstrap CIs, \textsc{SpanCall} outperforms both LLMs on scalar calls (0.798 and 0.840 vs.\ 0.360--0.397 and 0.755). Pairing \textsc{SpanCall} with abstention-gated LLM fallback (\textbf{Router}) reaches 0.807--0.808 macro \texttt{exact\_F} at 17.6\% fallback rate (80\% token savings, $4.5\times$--$5.2\times$ lower mean latency), and adding a deterministic post-$H_1$ schema-type gate for \texttt{array}/\texttt{object} tools (\textbf{Router+Schema}) lifts macro \texttt{exact\_F} to \textbf{0.855--0.857} (0.889 on xLAM) while still saving 60\% of tokens and cutting mean latency by $2.6\times$--$2.7\times$.
\end{itemize}
