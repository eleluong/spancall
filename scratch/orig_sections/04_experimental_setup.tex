\section{Experimental Setup}
\label{sec:setup}

\paragraph{Balanced training and validation.}
We train and evaluate on single-call turns from \textbf{NousResearch Hermes Function-Calling V1} \citep{teknium2024hermes} and \textbf{Salesforce xLAM-60k} \citep{zhang2024xlam}, excluding instances whose ground-truth tool is absent from the candidate schema list. To use all available data while preventing the larger corpus from dominating, we retain 100\% of xLAM training data (\textbf{69,412} instances) and upsample Hermes training data (19,096 $\rightarrow$ \textbf{69,412} instances) for an exact 1:1 corpus balance before tensorization (\textbf{117,760} training instances). Each upsampled Hermes copy receives a distinct random seed for distractor tool packing (up to 6 tools per instance from the combined schema pool), so every copy is paired with fresh distractor tools rather than verbatim duplicates. Held-out validation keeps both corpora separate---Hermes dev (669 rows, 1,239 span targets) and xLAM dev (2,384 rows, 4,145 span targets)---and selects the best checkpoint by their unweighted \textbf{macro-average} \texttt{exact\_call}. A disjoint 313-row probe set (559 targets, drawn from the calibration split with zero overlap with dev or eval) is scored every 2,000 optimizer steps. All splits are verified for span-offset alignment and marker-injection sanitization prior to evaluation.

\paragraph{Training configuration.}
We fine-tune \texttt{answerdotai/ModernBERT-large} ($L_{\max}{=}4096$, $W_{\max}{=}16$, $C{\le}1024$) for 3 epochs in \texttt{bf16}, with micro-batch 32 and gradient accumulation 4 (effective batch 128), cosine learning-rate decay with a 10\% floor, and best-checkpoint restoration on macro dev \texttt{exact\_call}.

\paragraph{Frozen fair evaluation benchmark and baselines.}
To eliminate cross-corpus size, cohort, and complexity skew, we construct a fixed two-tier evaluation benchmark:
\begin{itemize}
    \item \textbf{Tier~1 (Matched Fair Eval):} Hermes eval and xLAM eval each contain \textbf{1,735} single-call sanitized instances with \emph{exact 1:1 parity} across every $(\text{cohort} \times \text{complexity})$ cell (excluding Hermes-only JSON-mode rows): \textbf{1,277 Stratum~F} instances (1,108 \textsc{Normal}, 169 \textsc{Complex}; 13.2\% complex) and \textbf{458 Stratum~A} instances (286 clean ungroundable, 172 adversarial).
    \item \textbf{Tier~2 (Full ID, OOD \& Adversarial):} All eight full single-call sanitized splits across both corpora: Hermes ID eval ($n{=}1{,}829$), xLAM ID eval ($n{=}6{,}811$), Hermes OOD-Schema ($n{=}1{,}599$), xLAM OOD-Schema ($n{=}7{,}227$), Hermes OOD-Para ($n{=}1{,}342$), xLAM OOD-Para ($n{=}6{,}876$), Hermes Adversarial ($n{=}4{,}285$), and xLAM Adversarial ($n{=}5{,}000$).
\end{itemize}

On Tier~1, we compare \textsc{SpanCall} (two-step decoding, inference batch size 8) head-to-head against \textbf{two} hosted LLMs via the OpenAI SDK: \textbf{\texttt{google/gemma-4-26b-a4b-it}} and \textbf{\texttt{openai/gpt-oss-120b}} (temperature 0.0, identical inputs, tool schemas, context, and evaluator). We report four configurations per LLM: (i) \textsc{SpanCall} alone (abstentions score as misses), (ii) \textbf{LLM-only}, (iii) \textbf{Router} (\textsc{SpanCall} when it commits, falling back to the LLM when it abstains), and (iv) \textbf{Router+Schema} (post-$H_1$ schema-type gate routing to the LLM whenever the $H_1$-selected tool $\hat{t}$ declares an \texttt{array}/\texttt{object} parameter, plus abstention fallback; strictly leak-free with zero ground-truth access). All merged predictions are scored by the same evaluator; for \textbf{Router+Schema}, we conservatively charge the full \textsc{SpanCall} latency plus LLM latency on schema-routed rows (an upper bound, since only $H_1$ is needed). Both LLMs are evaluated \emph{zero-shot} with \texttt{tool\_choice=auto} and no explicit decline instruction; thus their \texttt{false\_hit\_on\_A} reflects this prompt rather than an intrinsic upper bound. We report 10,000-resample paired bootstrap 95\% confidence intervals for every \texttt{exact\_F} difference. \textsc{SpanCall}'s latency is amortised over batch size 8 on a single GPU, whereas LLM latency is a hosted network round trip; the two columns reflect realistic serving orders of magnitude rather than identical hardware. All runs use seed 42; code and evaluation splits will be released upon publication.
